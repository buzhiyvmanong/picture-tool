# 截图贴图标注工具探索

## 已确认路线

当前已确认走 Windows 原生路线：

- 第一实现：WPF
- 备选：WinUI / Windows App SDK
- 不作为正式低内存路线：Electron
- 暂不优先：Tauri

选择 WPF 的原因：

- 低内存要求更容易控制
- 托盘、全局快捷键、透明遮罩、置顶贴图窗口更贴近系统能力
- 不需要内置 Chromium
- 可以先把截图、标注、贴图这些核心桌面能力做稳

## 目标

做一个常驻桌面小工具，支持：

- 区域截图、窗口截图、全屏截图
- 截图后标注
- 粘贴剪贴板图片进入标注
- 截图后贴图到屏幕
- 多张贴图置顶、拖动、缩放、关闭
- 后续支持滚动截图

新增硬约束：

- 运行时不能占用太大内存
- 常驻状态要轻
- 截图、标注、贴图窗口按需创建
- 图片对象及时释放，避免多份大图常驻内存

## 技术路线判断

### 方案 A：Windows 原生应用

推荐程度：高，尤其适合先做 Windows 版。

可选技术：

- C# WPF / WinUI
- Rust + windows-rs / egui / wgpu
- C++ Win32 / Direct2D

优点：

- 内存更可控
- 贴图窗口、置顶窗口、透明窗口、全局快捷键、多屏 DPI 更容易贴近系统能力
- 截图、剪贴板、托盘、热键可以走系统 API
- 不需要内置 Chromium

缺点：

- 跨平台成本更高
- UI 研发效率低于 Web 技术栈

适合目标：

- 重点做 Windows 桌面效率工具
- 低内存是明确要求
- 希望体验接近 Snipaste、PixPin 一类工具

### 方案 B：Tauri + 轻量前端

推荐程度：中高，适合想兼顾轻量和跨平台。

可选技术：

- Tauri
- Rust
- Solid / Svelte / Preact
- Canvas / Konva-lite 自研标注层

优点：

- 比 Electron 轻
- 可以用 Rust 做截图、贴图窗口、快捷键、托盘
- UI 开发体验比纯原生好
- 后续具备跨平台空间

缺点：

- WebView 仍然有一定内存成本
- 贴图窗口、鼠标穿透、多屏 DPI、滚动截图仍需要较多原生处理
- 当前机器没有 Rust 环境，暂时不能直接构建运行

适合目标：

- 想要跨平台
- 可以接受比纯原生稍高的内存
- 希望前端界面开发更快

### 方案 C：Electron + React

推荐程度：低，不建议作为低内存正式路线。

优点：

- 开发最快
- 截图编辑界面好做
- 多窗口和剪贴板能力成熟

缺点：

- 常驻内存偏大
- 多贴图窗口会进一步增加内存压力
- 打包体积大

适合目标：

- 只做快速交互验证
- 不把内存占用作为硬指标

## 推荐结论

如果你的核心要求是“截图 + 标注 + 贴图 + 常驻轻量”，首选：

1. Windows-only：C# WPF / WinUI 或 Rust 原生
2. 跨平台：Tauri + Rust + Svelte/Solid
3. 快速演示：Electron，但不作为正式低内存路线

当前我更建议先走：

**Windows 原生优先，Tauri 作为第二选择。**

原因：

- 截图工具的核心难点在系统能力，不在普通页面 UI
- 贴图窗口本质是大量轻量置顶窗口
- 低内存要求下，应尽量避免每个贴图都依赖重型渲染上下文
- 标注数据可以用矢量命令保存，导出时再合成图片

## 内存控制设计

### 进程模型

- 常驻主进程只负责托盘、快捷键、配置和窗口调度
- 截图遮罩窗口按需打开，用完关闭
- 标注编辑窗口按需打开，用完关闭
- 贴图窗口是轻量无边框置顶窗口
- 滚动截图模块延迟加载

### 图片存储

- 不用 base64 在进程间传大图
- 大图优先使用临时文件路径或系统 bitmap handle
- 同一张截图只保留一份原图
- 标注层保存为矢量命令
- 导出时再把原图和标注合成 PNG

### 撤销重做

不要保存每一步的整张图片快照。

推荐保存：

- arrow command
- rect command
- brush path command
- text command
- mosaic region command
- crop command

这样撤销重做只操作命令栈，内存压力小很多。

### 贴图窗口

每张贴图只保留：

- 图片引用
- 位置
- 尺寸
- 透明度
- 置顶状态
- 是否鼠标穿透

关闭贴图时立即释放图片资源。

### 滚动截图

滚动截图最容易吃内存，需要单独控制：

- 限制最大截图高度
- 分段截图
- 边拼接边释放旧帧
- 重叠区域只保存必要数据
- 超大图先写临时文件，不长期放在内存里

## MVP 功能顺序

### 第一阶段

- 托盘入口
- 全局快捷键
- 区域截图
- 截图后进入标注
- 标注箭头、矩形、画笔、文字、马赛克
- 复制到剪贴板
- 保存到文件

### 第二阶段

- 截图后贴图到屏幕
- 多贴图
- 拖动、缩放、透明度
- 始终置顶
- 鼠标穿透

### 第三阶段

- 剪贴板贴图进入编辑器
- 拖拽图片进入编辑器
- 贴图双击进入标注
- 历史记录

### 第四阶段

- 网页滚动截图
- 通用应用滚动截图
- 拼接误差修正

## 当前环境检查

当前目录是空目录，可以从零开始。

已具备：

- Node.js
- npm

暂未具备：

- Rust / Cargo
- .NET SDK
- MSBuild
- C++ 编译器

因此当前机器如果要直接做低内存正式原型，需要先安装其中一种原生开发环境：

- 走 Tauri / Rust 原生：安装 Rust
- 走 WPF / WinUI：安装 .NET SDK
- 走 C++ 原生：安装 Visual Studio Build Tools

## 下一步建议

低内存优先时，不建议继续搭 Electron。

下一步可以二选一：

1. Windows 原生路线：先安装 .NET SDK，做 WPF / WinUI 原型
2. 跨平台轻量路线：先安装 Rust，做 Tauri 原型

如果只想先看交互样子，可以临时做一个 Web 编辑器原型，但它不能代表真实内存表现。
